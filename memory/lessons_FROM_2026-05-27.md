## Key Lesson #1: Dual Gateway Process Conflict

**What happened:** After updating Gemini API key in config, systemctl restart kept failing with exit code 78 (port occupied). Two gateway processes were fighting on port 18789 — the old PID (2881808) from the interactive session still held the port with the expired key, while systemd tried spawning a new one.

**Root cause:** OpenClaw gateway instance running from interactive session survives systemctl restarts. Every `systemctl restart openclaw` spawned a zombie that crashed immediately on the occupied port.

**Fix:** Kill the old gateway process first (`kill <PID>`), THEN restart via systemd. One file change, one restart.

**Lesson:** Kill old gateway BEFORE updating config + restarting. One file, one restart.

## Key Lesson #2: API Key Rotation Requires Multi-Location Update

**What happened:** Old Gemini key expired, broke memory search silently. New key had to be updated in 4 separate locations.

**Files to update when rotating Gemini key:**
1. `~/.openclaw/secrets.json`
2. `~/.openclaw/auth-profiles.json`
3. `~/.openclaw/models.json`
4. Systemd service environment (`/etc/systemd/system/openclaw.service` or override)

**Lesson:** Always check all 4 locations when rotating API keys. Update a checklist in TOOLS.md for future key rotations.
